Tên dự án: giữ SmartStay, vì sơ đồ Use Case của nhóm đã dùng tên này.

Antigravity là nơi AI viết code: bạn mở thư mục gốc E:\SmartStay trong đó, dán từng prompt vào Agent, rồi mở Visual Studio hoặc Android Studio để chạy thử.

Prompt 1 – Khởi tạo và Backend API

Bạn là lập trình viên .NET senior. Làm việc trong thư mục E:\SmartStay.

BƯỚC 0: Tạo file docs/CONTEXT.md ghi lại toàn bộ bối cảnh dưới đây (các prompt sau sẽ đọc file này).

# BỐI CẢNH
Đề tài: "Hệ thống quản trị hệ sinh thái lưu trú thông minh đa nền tảng" (tên dự án SmartStay), phục vụ ký túc xá/nhà trọ/căn hộ dịch vụ.
Tác nhân: Admin, Quản lý vận hành (Admin kế thừa mọi quyền), Nhân viên kỹ thuật, Cư dân.
Kiến trúc: Backend ASP.NET Core Web API (.NET 8, EF Core, SQL Server, JWT, SignalR) là trung tâm; Web Admin ASP.NET Core MVC; Mobile Flutter. Giao diện tiếng Việt.
CSDL SQL Server ĐÃ CÓ SẴN (32 bảng, tên tiếng Việt không dấu, khóa chính dạng MaXxx). KHÔNG tự thiết kế lại bảng, KHÔNG đổi tên bảng/cột:
- Tài khoản: VaiTro, NguoiDung(MaNguoiDung, TenDangNhap, ThuDienTu, SoDienThoai, MaBamMatKhau, HoTen, MaVaiTro, DangHoatDong, CanDoiMatKhau, LanDangNhapCuoi), MaDatLaiMatKhau, NhatKyKiemToan
- Hạ tầng: ToaNha, LoaiPhong, Phong(trạng thái Trống/Đang ở/Bảo trì/Đã đặt), TaiSanPhong
- Cư dân & hợp đồng: CuDan, HopDong, CuDanHopDong(N-N, LaDaiDien), BienBanBanGiao, TaiSanBanGiao
- Điện nước & hóa đơn: DichVu, BacGia(biểu giá bậc thang có hiệu lực), DichVuHopDong, ChiSoSuDung, HoaDon, ChiTietHoaDon, ThanhToan
- Sự cố: DanhMucSuCo, PhieuSuCo, HinhAnhSuCo, TraoDoiSuCo, LichSuSuCo
- Thông báo & sự kiện: ThongBao, ThongBaoHeThong, ThietBiThongBao, SuKien, DangKySuKien
- Trợ lý AI: PhienTroChuyen, TinNhanTroChuyen
Giá trị trạng thái/loại: đọc từ dữ liệu và ràng buộc thực tế trong DB, không tự bịa.
Nghiệp vụ chính: hóa đơn hàng tháng = tiền phòng + điện/nước tính theo bậc thang (mỗi bậc một dòng ChiTietHoaDon) + dịch vụ cố định + giảm trừ; phát hành hóa đơn thì sinh mã VietQR (URL dạng https://img.vietqr.io/image/{BIN}-{SoTK}-compact2.png?amount=..&addInfo=..&accountName=..); cư dân tải ảnh biên lai -> ThanhToan "chờ xác nhận" -> quản lý đối soát; sự cố đi qua Chờ xử lý -> Đang sửa -> Hoàn thành, mỗi lần đổi trạng thái ghi LichSuSuCo + thông báo đẩy; Check in/Check out lập biên bản, chốt chỉ số, tính hoàn cọc.

BƯỚC 1: Tạo solution SmartStay.sln và project SmartStay.Api (Web API, .NET 8).
BƯỚC 2: Tạo model từ DB có sẵn (database-first):
dotnet ef dbcontext scaffold "Server=.;Database=SmartStayDB;Trusted_Connection=True;TrustServerCertificate=True" Microsoft.EntityFrameworkCore.SqlServer -o Models --context-dir Data -c SmartStayDbContext --force
(Tên server/DB để trong appsettings.Development.json, không hard-code. JWT key, API key dùng dotnet user-secrets.)
BƯỚC 3: Xây dựng API (Controllers mỏng, logic ở Services, trả về DTO, có Swagger, validate, ghi NhatKyKiemToan cho thao tác quan trọng):
1. Xác thực: đăng nhập JWT (claims: MaNguoiDung, vai trò), đổi mật khẩu, quên mật khẩu (MaDatLaiMatKhau), bắt buộc đổi mật khẩu lần đầu; băm mật khẩu bằng BCrypt.Net-Next; phân quyền theo vai trò ([Authorize(Roles=...)]).
2. Tòa nhà, loại phòng, phòng, tài sản phòng; endpoint sơ đồ phòng theo tầng.
3. Cư dân (tự tạo tài khoản NguoiDung vai trò Cư dân, kiểm tra trùng số căn cước/SĐT, import Excel bằng ClosedXML), hợp đồng (kiểm tra phòng khả dụng, thêm người ở cùng, gia hạn/thanh lý, xuất PDF bằng QuestPDF), Check in/Check out (BienBanBanGiao, TaiSanBanGiao, tính hoàn cọc).
4. Dịch vụ, BacGia, nhập/import ChiSoSuDung (kiểm tra bất thường, báo phòng thiếu chỉ số), tạo hóa đơn nháp hàng loạt theo kỳ (tính bậc thang đúng theo BacGia hiệu lực), phát hành hóa đơn (sinh QR), ThanhToan (cư dân gửi biên lai, quản lý xác nhận/từ chối, cập nhật trạng thái hóa đơn), nhắc nợ/quá hạn bằng BackgroundService.
5. Sự cố: tạo phiếu (upload ảnh/video vào wwwroot/uploads), phân công, đổi trạng thái hợp lệ, trao đổi, đánh giá 1–5 sao, lịch sử.
6. Thông báo nội khu (theo phạm vi tất cả/tòa nhà/tầng/cá nhân, hẹn giờ), sự kiện và đăng ký/điểm danh, ThongBaoHeThong, đăng ký ThietBiThongBao, gửi push qua Firebase Admin SDK.
7. Dashboard (KPI, doanh thu, công nợ, tỷ lệ lấp đầy, việc cần xử lý), báo cáo xuất Excel/PDF.
8. SignalR Hub: cập nhật sơ đồ phòng và Kanban sự cố theo thời gian thực.
9. Trợ lý AI: endpoint /api/tro-ly/chat gọi Gemini API từ server (key không đưa xuống app), lưu PhienTroChuyen/TinNhanTroChuyen, đưa nội quy và hóa đơn của cư dân vào ngữ cảnh.
10. CORS cho web và mobile, xử lý lỗi tập trung (ProblemDetails), phân trang cho danh sách.
Mỗi nhóm xong thì chạy dotnet build, viết vài unit test cho phần tính hóa đơn bậc thang, rồi cập nhật README. Không dừng lại hỏi nhiều; có chỗ mơ hồ thì nêu giả định ngắn rồi làm tiếp.

Prompt 2 – Web Admin (MVC)

Đọc docs/CONTEXT.md. Trong solution SmartStay.sln, tạo project SmartStay.Web (ASP.NET Core MVC .NET 8, Bootstrap 5, Chart.js). Web chỉ gọi SmartStay.Api qua HttpClient (service lớp riêng), lưu JWT trong cookie HttpOnly, không truy cập DB trực tiếp. Giao diện tiếng Việt, responsive; Nhân viên kỹ thuật thấy giao diện rút gọn tối ưu trên điện thoại.
Layout: sidebar theo vai trò, thanh trên có chuông thông báo, avatar.
Màn hình: Đăng nhập/đổi mật khẩu; Dashboard (thẻ KPI, biểu đồ cột doanh thu-công nợ, biểu đồ tròn lấp đầy, danh sách việc cần xử lý); Sơ đồ phòng theo tầng (màu: Trống xanh lá, Đang ở xanh dương, Bảo trì cam, Đã đặt tím, cập nhật realtime bằng SignalR); Quản lý tòa nhà/phòng/tài sản; Hồ sơ cư dân (có import Excel); Hợp đồng (tạo, gia hạn, thanh lý, xuất PDF); Check in/Check out; Cấu hình biểu giá bậc thang; Nhập/Import chỉ số điện nước; Hóa đơn (tạo nháp hàng loạt, xem lại, phát hành, lọc theo trạng thái, xuất Excel công nợ); Đối soát thanh toán (xem ảnh biên lai, xác nhận/từ chối); Sự cố dạng bảng Kanban 3 cột Chờ xử lý/Đang sửa/Hoàn thành có kéo thả và gán nhân viên; Thông báo & Sự kiện (hẹn giờ, danh sách đăng ký, xuất điểm danh); Báo cáo; Quản lý tài khoản, phân quyền, cấu hình đơn vị (tài khoản ngân hàng cho VietQR), nhật ký hoạt động.
Làm lần lượt, mỗi màn xong chạy được và có xử lý lỗi/loading/rỗng. Cuối cùng cập nhật README cách chạy cả Api và Web cùng lúc.

Prompt 3 – Mobile Flutter

Đọc docs/CONTEXT.md. Tạo project Flutter smartstay_mobile trong E:\SmartStay (flutter create --org com.smartstay --project-name smartstay_mobile smartstay_mobile). Dành cho Cư dân, chạy Android và iOS, Material 3, tiếng Việt.
Cấu trúc lib: models, providers, services (api_client dùng dio + interceptor gắn JWT, tự refresh khi hết hạn), screens, widgets, utils. Quản lý trạng thái: provider. Lưu token bằng flutter_secure_storage. Base URL cấu hình được (emulator Android dùng http://10.0.2.2:<port>).
Gói: provider, dio, flutter_secure_storage, firebase_core, firebase_messaging, signalr_netcore, image_picker, intl, cached_network_image, url_launcher, open_filex.
Màn hình: Đăng nhập và đổi mật khẩu lần đầu; Trang chủ (thông tin phòng, hóa đơn cần đóng, sự cố đang xử lý, thông báo mới); Hợp đồng và tài sản bàn giao (xem, tải PDF); Hóa đơn (danh sách, chi tiết từng bậc thang điện nước, thanh toán bằng mã VietQR, tải ảnh biên lai, lịch sử thanh toán); Báo sự cố (chọn loại, mô tả, mức khẩn cấp, chụp ảnh/quay video, theo dõi tiến độ 3 bước, nhắn phản hồi, đánh giá 1–5 sao); Bảng tin (thông báo nội khu, sự kiện, đăng ký/hủy); Trợ lý ảo AI (giao diện chat, gọi /api/tro-ly/chat); Cá nhân (thông tin, đổi mật khẩu, cài đặt thông báo, đăng xuất).
Nhận thông báo đẩy bằng FCM và gửi token lên ThietBiThongBao. Có loading/rỗng/lỗi mạng cho mọi danh sách, pull-to-refresh. Chạy flutter analyze không còn lỗi, viết vài widget test, cập nhật README.

Trước khi dán, bạn thay SmartStayDB bằng đúng tên database của nhóm. Nếu bạn gửi mình file .sql hoặc ảnh sơ đồ DB mới nhất, mình bổ sung đầy đủ cột vào CONTEXT để AI ít đoán sai hơn. Nếu bạn muốn dùng chung một mã nguồn cho cả web lẫn mobile thay vì làm Web MVC riêng, mình viết lại Prompt 2 theo hướng Flutter Web.
